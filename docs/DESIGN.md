# Design Decisions – "Hochstapler" (private real-estate board game)

This document is the **living source of truth** for all design decisions.
New decisions are appended at the bottom in the decision log (ADR style, numbered).
Existing decisions are never deleted, but marked "superseded by #NN" (Hochstapler = "impostor/high-flyer", the game's name).
The document is written in English from now on; rows and sections written before the language switch were translated from German.

---

## 1. Goal

- Stylish 3D real-estate board game for private use, playable in the browser.
- Selectable country (Switzerland, France, Germany, …) → street names, stations, currency, cards, tokens and surroundings adapt.
- Larger board than the original (52 instead of 40 spaces).
- Houses → hotel → **skyscraper** (additional build level).
- Multiplayer via invite link, mixed with bots, or solo against bots.
- Long games (over days) possible: turn time limit, after which a bot takes over.
- Trading/swapping between players.

## 2. Tech stack (decisions #1, #2)

| Part | Choice | Rationale |
|---|---|---|
| Language | TypeScript everywhere | already on the machine, one type system for client + server |
| Monorepo | npm workspaces (`packages/*`) | no additional tools |
| `@poly/engine` | pure TS, no dependencies | game rules, bots, themes; runs on server **and** client |
| `@poly/server` | Node 25, `ws` + `node:http`, `node:sqlite` | authoritative server, persistence without native modules |
| `@poly/client` | Vite + Three.js + Preact (HUD) | 3D board with Three.js, UI overlay with Preact |
| Tests | vitest | fast, TS-native |
| TS execution | `tsx` (server), Vite (client) | engine is imported as TS source, no build step needed |

TS rules: `strict`, no `enum`s, no parameter properties (compatible with type stripping).

## 3. Architecture

```
Browser (Client)                      Server (Node)
┌───────────────────────┐   WS        ┌──────────────────────────┐
│ Three.js scene        │◄──────────► │ GameRoom per game        │
│ Preact HUD            │  JSON msgs  │  ├ engine.applyAction()  │
│ engine (types only,   │             │  ├ bot scheduler         │
│  theme data, helpers) │   REST      │  ├ turn timer            │
│                       │◄──────────► │  └ SQLite (state + log)  │
└───────────────────────┘  /api/...   └──────────────────────────┘
```

- **Server-authoritative**: clients only send *intents* (`GameAction`). The server validates with the engine and broadcasts the new state plus `GameEvent`s (for animations).
- **The engine is pure and deterministic**: `applyAction(state, playerId, action, now)` → `{ state, events }` or an error. Randomness comes from a seed in the state (mulberry32). Time is passed in as a parameter.
- **Solo mode also runs through the local server** (one code path).
- The server sends the state redacted (`redactState`: without RNG seed and card order).
- In production a single process serves the API, WebSocket and the built client files.

## 5. Rules (decision #4)

Classic property-trading rules with the following specifics:
- Starting cash 2000, GO = 200 (option: double on exact landing).
- Roll 2d6; doubles → roll again; 3rd doubles → jail.
- Jail: max. 3 attempts to roll doubles, bail 50, get-out-of-jail card possible.
- Buy or decline → **auction** (option, on by default). Bids may exceed cash on hand (decision #35); whoever wins without enough cash must raise the money or declare bankruptcy.
- **Build levels per street**: 0 empty, 1–4 houses, 5 hotel, **6 skyscraper**.
  - Build evenly (level difference within a group max. 1).
  - Skyscraper only once **all** streets of the group have a hotel. It costs 2× the build cost.
  - Bank supply: 48 houses, 16 hotels, 8 skyscrapers (option).
- Mortgages: 50 % of the price, repayment +10 %.
- When in debt, buildings can be sold (50 %) and mortgages taken out, otherwise bankruptcy. On bankruptcy to a player everything goes to that player; to the bank it is auctioned or returned.
- Rest-stop jackpot: option, off by default.
- End of game: only one player not bankrupt, optionally a round limit, or **by vote** (#42): any player can propose ending the game; if all agree, the highest net worth wins (cash + properties + buildings − mortgages; tie: more cash, then earlier seat order). The same ranking applies at the round limit.

## 6. Trading (decision #5)

- Any player can make another player an offer **at any time**: money, properties (without buildings), get-out-of-jail cards – in both directions.
- An offer stays open until it is accepted, declined, withdrawn or becomes invalid. It is validated again on acceptance.
- Mortgaged properties may be traded, the recipient pays the 10 % interest (simplified: immediately).
- Bots evaluate offers heuristically (value + colour-set potential) and make offers themselves when they are missing one street for a full colour set.
- Offers to absent humans expire after the turn timeout (declined).

## 7. Multiplayer, invitation, long games (decision #6)

- No accounts. The host creates a game: country, settings, number of bots, time limit.
- Invite link: `/#/join/<gameId>/<inviteCode>`. Whoever joins enters a name and receives a secret `playerToken` (in `localStorage`, per game) → reconnect from any device with the same link plus token.
- Lobby → host starts → game runs. Max. 8 players (human + bot).
- **Turn time limit** (`turnTimeoutSec`, e.g. 60 s live or 24 h for correspondence games, 0 = off):
  - When a human's time runs out, the bot makes **that** decision or turn.
  - After `awayAfterMissedTurns` (default 2) missed turns the player is considered `away`. The bot then plays all of their turns immediately until the human sends an action again (then `human`).
- Persistence: SQLite file `data/games.sqlite` (lobby, current state, action log). A server restart resumes all games including timers.
- Online play with friends: run the server locally and expose it via a tunnel (e.g. `cloudflared tunnel`), or deploy to a small host (Fly.io/Render). See README.

## 8. Country themes (decision #7)

The engine only knows space indices and card IDs. A **theme** provides:
`id, name, locale, currency {code, symbol, position}`, names of all 52 spaces, group colours and names, texts for every card ID, tokens (6–8 thematic token IDs with names), surroundings (e.g. `alps`, `paris`, `berlin`) for the 3D backdrop, landmark model for the board centre.
- Money amounts are the same in all countries, only the currency symbol changes (CHF / €).
- Starting themes: 🇨🇭 Switzerland, 🇫🇷 France, 🇩🇪 Germany, 🇮🇹 Italy.
- The UI language is German (later also en/gsw, see the log); space names are in the country's language.

## 9. 3D client & style (decision #8)

- Three.js. Board as a tabletop scene with soft light, shadows, light bloom; low-poly/"tabletop diorama" look in pastel colours.
- Space labels via canvas textures (no font assets needed).
- **Asset pipeline**: `packages/client/public/assets/models/*.glb` + `manifest.json`. If a model is missing, a procedural fallback geometry is used → the game is always playable, and Meshy models can simply be copied in.
- Dice: the result comes from the server, the client animates the roll to match.
- Camera: orbit plus "follow active token", zoom to a space on click (info card).
- Asset briefs for Meshy/Codex: `docs/ASSETS.md`.

## 10. Bots (decision #9)

Levels `easy | normal | hard`, deterministic via the game RNG. Heuristics: buy when reserve > X; build on full colour sets; mortgage to avoid bankruptcy; trade to complete colour sets. Bots run on the server with a short delay (~700 ms) per action so the animations are visible.
